# 默认复刻范围（用户确认版）

调用本 Skill 时，除非用户另行指定，一律按下列范围执行。用户确认拥有复刻该网站及使用相关页面内容、品牌元素和媒体素材的合法权限。

## 一、最终目标

在当前 Next.js 项目中重建目标 URL 对应的页面，使本地版本在桌面端的视觉效果、内容结构和前端交互上尽可能接近原网站。

复刻结果必须是可以正常运行、继续编辑和部署的真实前端项目，不能只生成截图、静态设计稿或无法维护的单文件演示。

## 二、页面范围

1. 只复刻当前 URL 实际展示的页面。
2. 包含页面中的导航栏、首屏、内容区块、卡片、按钮、表单外观、页脚、悬浮元素、弹窗、下拉菜单和其他可见组件。
3. 除非当前页面的交互必须使用，否则不继续复刻链接指向的其他页面。
4. 页面内的锚点跳转、标签切换、弹窗和下拉菜单需要保留。
5. 如果目标 URL 存在多个视觉状态，需要提取并还原所有可见状态。

## 三、设备范围

1. 只制作桌面端。
2. 以 `1440px` 宽度作为主要视觉验收基准。
3. 不需要制作平板端、移动端或专门的响应式布局。
4. 不要为移动端添加汉堡菜单、移动端导航、触摸手势或移动端断点。
5. 页面在桌面浏览器中不能出现意外的水平滚动、布局溢出、文字遮挡或组件错位。
6. 原站存在的桌面端最大内容宽度、居中规则和两侧留白需要准确还原。

## 四、前后端边界

这是一个纯前端复刻任务，不需要任何真实后端能力。

不要实现以下内容：

- 数据库
- 用户注册和登录
- 身份验证
- 支付功能
- 邮件发送
- 文件上传服务
- API Route
- Server Action
- WebSocket
- 第三方业务接口
- 管理后台
- 内容管理系统

如果页面包含登录、搜索、订阅、联系、购买或提交表单：

- 只还原前端外观和交互状态。
- 使用本地模拟数据。
- 可以模拟加载、成功、失败、空状态和禁用状态。
- 不发送真实网络请求。
- 不保存用户提交的数据。
